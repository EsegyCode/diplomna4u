```css
     border-radius:var(--r-btn);padding:14px 28px;font-weight:600;transition:.2s}
.btn:hover{background:transparent;color:var(--s-accent)}      /* hover = інверсія */
.btn--ghost{background:transparent;color:var(--s-accent)}
.btn--ghost:hover{background:var(--s-accent);color:var(--s-on)}
```

Висота кнопок/CTA ≥ `--tap-min` (48px); `:focus-visible` — контурна рамка контрастного до фону секції кольору (`--s-accent`) з відступом 3px. Колір `--deep-hover` — для hover заливних елементів поза `.btn` (напр. посилання-плитки); `.btn` інвертується за правилом вище.

### Тема секцій і ритм

Теми застосовуються класами `section`, `section--surface|sage|invert`; футер — фон `--deep`, текст `--bg`. Ритм головної — таблиця в **A7**. Дві однакові теми підряд не ставити (виняток: секція 8 → Footer, див. A7).

### Розділювач `WaveDivider`

- Компонент `WaveDivider.astro`: inline SVG (`aria-hidden="true"`, `preserveAspectRatio="none"`, `width:100%`, висота 40–96px залежно від брейкпоінту), варіанти `wave` (органічна хвиля) і `drop` («крапля»); чергувати варіанти між секціями, щоб не виглядало шаблонно.
- Заливка хвилі = колір **наступної** секції (`fill: var(--next-bg)`), хвиля розташована внизу поточної секції; відкид `transform: scaleY(-1)` — для хвилі зверху.
- Кожна секція отримує `--next-bg` від батьківського шаблону (з масиву секцій сторінки), а не жорстко.
- Не використовувати пряму лінію чи `border-bottom` між секціями.

### Картки «шахматкою»

У рядку з 4 карток: 1 і 3 світлі (`surface` + рамка 1px `tint`), 2 і 4 темні (`deep`, текст `--bg`). Кнопка в темній картці інвертується автоматично, бо картка задає власну тему:

```css
.card{--s-bg:var(--surface);--s-fg:var(--ink);--s-accent:var(--deep);--s-on:var(--bg);
      background:var(--s-bg);color:var(--s-fg);border:1px solid var(--tint);border-radius:var(--r-card)}
.card--dark{--s-bg:var(--deep);--s-fg:var(--bg);--s-accent:var(--bg);--s-on:var(--deep);border-color:var(--deep)}
```

- Чергування — CSS, а не ручні класи: 4 колонки (desktop) — `:nth-child(even)` темні; 2 колонки (планшет/мобільний) — `:nth-child(4n+2), :nth-child(4n+3)` темні, щоб вийшла справжня шахівниця, а не смуги; 1 колонка — парні темні.
- Якщо карток не кратно 4 — шахматка продовжується за тим самим правилом.
- Картка в секції `invert` не повинна зливатися з фоном: темні картки там мають рамку `1px solid var(--sage)`; світлі лишаються `surface`.

### Форма й калькулятор

- Картка `QuickOrder`/`LeadForm` **завжди світла** (`bg`, `--shadow-card`), навіть усередині темної секції. Картка задає власну світлу тему (як `.card`, але з `--s-bg: var(--bg)`), тому `.btn` усередині — бордовий.
- Поля: фон білий (`#fff` — єдиний допустимий hex поза палітрою, винести в `--field-bg` у `:root`), рамка 1px `--sage`, радіус `--r-input`, фокус: рамка `--deep`; помилка: рамка й текст `--error` + текстове повідомлення (не лише колір).
- Повзунок унікальності: доріжка `--sage`, ручка `--deep`; бабл зі значенням; кнопки −/+ у колі з рамкою `--sage`.
- Кнопка «Дізнатися вартість» — `.btn`.
- Ціна «від …» — великим шрифтом кольору `--deep`; бейдж «Ціна від X грн» зверху картки на фоні `--tint`, текст `--deep`.

### Липка кнопка зв'язку (`StickyContact`)

Коло `--deep` з кремовою (`--bg`) іконкою та кремовою обводкою 3px + тінь, щоб було видно і на темних, і на світлих секціях. Панель, що відкривається: світла картка (як форма), кнопки Telegram/Viber — `.btn`/`.btn--ghost`. Мобільна нижня панель: фон `--deep`, текст і іконки `--bg`.

### Доступність

- Текст на `sage` — лише `--deep` або `--ink`. **Ніколи `sage` як колір тексту** на кремовому.
- Основний текст — `--ink`, другорядний — `--muted` (тільки на `--bg`/`--surface`, не на `sage`).
- Контраст ≥ 4.5:1 для тексту; перевірити пари: `--ink/--bg`, `--deep/--sage`, `--bg/--deep`, `--muted/--surface`; невідповідність — у звіт.
- Стан кнопки при hover (`transparent` + рамка) теж має тримати контраст у кожній темі секції.

### Загальні правила

- Mobile-first, основний брейкпоінт **900px**; тач-зони: CTA ≥ 48px, інші ≥ 44×44px.
- Іконки — inline SVG (outline). Усім `<img>`: `alt`, `width`/`height`, `loading="lazy"` (крім hero).
- Анімації легкі, `prefers-reduced-motion` вимикає (pulse липкої кнопки, переходи `.btn`).

### Відправка заявок у Telegram (serverless)

Статична збірка не обробляє POST, а токен бота **не можна** класти в клієнтський код. Тому:

1. `functions/api/lead.ts` (Cloudflare Pages Function; для Netlify — еквівалент у `netlify/functions`): приймає `POST` JSON, перевіряє метод, обов'язкові поля, довжини, honeypot; відправляє повідомлення через `https://api.telegram.org/bot<TOKEN>/sendMessage` з `chat_id` із середовища; повертає `{ ok: true }` або `{ ok: false }` без деталей.
2. Змінні середовища (**значення не зберігати в репозиторії, коді чи цьому файлі**): `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`. У репозиторії — лише `.env.example` з іменами; `.env` у `.gitignore`.
3. Текст повідомлення (HTML, усі значення екранувати):
   ```
   🆕 Нова заявка · diplomna4u
   Тип: … · Напрям: … · Сторінок: … · Унікальність: … · Термін: … · Додатково: …
   Орієнтовна ціна: … грн
   Ім'я: … · Контакт: … · Коментар: …
   Джерело: … · Сторінка: … · Місто: …
   ```
4. Клієнт: `LeadForm` шле на `PUBLIC_LEAD_ENDPOINT` (за замовчуванням `/api/lead`). **`MOCK_MODE = !import.meta.env.PUBLIC_LEAD_ENDPOINT`** — у dev/без змінної імітується успіх (`setTimeout`), без `fetch`.
5. Не логувати персональні дані; не віддавати токен у відповідях і помилках.
6. `src/pages/api/lead.ts` — лише заглушка-коментар (SSG не обслуговує її).
7. У фінальному звіті окремо нагадати: заявки **не приходитимуть**, поки на хостингу не задані `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` і не задеплоєна функція.
